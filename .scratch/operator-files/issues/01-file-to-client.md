# 01. Менеджер отправляет клиенту файл

Status: done

Отправка из окна переписки: кнопка «Файл», перетаскивание в поле ответа,
вставка из буфера. Слова из поля уходят подписью.

## Сделано

- `@nemo/telegram/files.ts` — `sendClientFile`: `sendPhoto` для картинок
  до 10 МБ, иначе `sendDocument`, с повтором файлом на отказ по
  картинке. Возвращает описание принятого файла из ответа Telegram.
- `@nemo/core`: `ReplyInput` принимает `attachment`, `body` стал
  необязательным (файл бывает сам себе ответом); при вложении операция
  уведомлений не возвращает. `operatorCaption` рядом с
  `OPERATOR_PREFIX`. `clientExists` — проверка до отправки.
  `logMessageAttachmentView` пропускает исходящие.
- `apps/admin/app/api/conversations/attachments/route.ts` — приём формы,
  предел 20 МиБ, подпись до 1024 знаков, отказ Telegram отдельным
  ответом 502 со словами.
- `apps/admin/app/ui/dialog.tsx` — выбор файла, полоса с выбранным,
  отказ до отправки, перетаскивание и вставка.

## Проверено

- Тесты ядра (`conversations.test.ts`): вложение сохраняется исходящим,
  уходит без подписи, уведомлений не порождает, пустое отвергается, в
  журнал доступа не пишется.
- Тесты `@nemo/telegram` (`files.test.ts`): картинка → `sendPhoto` с
  крупнейшим размером, прочее → `sendDocument` с именем, подпись без
  слов, повтор файлом, отказ наружу.
- Живьём на своей машине: форма принимает файл перетаскиванием, маршрут
  доходит до Telegram и отвечает словами на отказ (клиент 5003
  выдуманный, чата у него нет). Исходящий пузырь с файлом нарисован.

## Осталось человеку

Живая отправка настоящему клиенту с боевого или тестового контура:
дошёл ли файл, как он выглядит у клиента в чате и открывается ли обратно
в панели.
