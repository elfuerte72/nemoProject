# Очередь под рост: поиск, фильтры, липкая шапка, предел выборки

Status: ready-for-agent

Владелец: на старте десятки заявок в день, строить с расчётом на рост.
Сейчас очередь этого не выдержит:

- ни поиска, ни фильтров: клиент написал «что с моей заявкой» — менеджер
  ищет его глазами по всему списку;
- шапка таблицы уезжает при прокрутке (`sticky` в панели есть у меню и
  карточки клиента, у `.table__head` — нет);
- выборки без предела: `listExchangeRequestQueue` и
  `listExchangeRequestsInProgress` (`packages/core/src/exchange-workflow.ts:251-284`)
  отдают все строки, «В работе» и «Разобранные» будут расти неограниченно.

## Что делать

1. Поиск по нику и номеру клиента; фильтры по состоянию и виду (наличные
   / безналичные) с явной отметкой, что фильтр включён, — иначе человек
   забывает, что смотрит подмножество.
2. `position: sticky` для шапки таблицы. На узком экране шапки нет —
   там ничего не меняется.
3. Предел выборки и подгрузка курсором по `createdAt`; порядок очереди
   остаётся «старые сверху» — это срок ожидания клиента.
4. Индексы под новые выборки в `@nemo/db` (состояние + дата, клиент).

## Как проверяем

Тестами: фильтр по состоянию не отдаёт чужие состояния, поиск по нику
находит запись, предел соблюдается, курсор не теряет и не дублирует
строки на границе. Вёрстка фильтров — глазами, в том числе на телефоне.

## Что не делаем

Виртуализацию списков и серверную пагинацию с общим числом страниц: при
десятках строк это работа впустую. Курсор и предел — достаточная
заготовка.
