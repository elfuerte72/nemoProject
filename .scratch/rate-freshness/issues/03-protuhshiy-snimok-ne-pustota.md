# Протухший снимок не отдаётся пустотой

Status: ready-for-human

`current()` отдаёт снимок старше потолка и уходит обновляться в фоне, а
`read()` тут же выбрасывает его — клиент получает пусто при живом
провайдере, который ответил бы за две десятых секунды. Воспроизведено:

```
первый визит: ПУСТО; следующий опрос: курс есть; запросов к провайдеру: 3
```

Показывать нечего — значит надо дождаться обновления, ровно как ждёт его
первый клиент после запуска процесса.

Признак «уже ждали и не дождались» сейчас ставится навсегда. Его надо
сбрасывать удачным обновлением: иначе после первого же протухания ждать
не станет никто.

- Acceptance:
  - снимок старше `maxAgeMs` при живом провайдере приводит к ожиданию, а
    не к пустоте;
  - молчащий провайдер по-прежнему заставляет ждать только одного
    клиента, остальные получают пусто сразу;
  - удачное обновление снимает признак;
  - ожидание из-за протухания пишется в журнал: событие редкое, и о
    пропаже курса в логах не должно быть пусто, как сейчас.
- Verify: `cd packages/rates && pnpm run test`.
- Files: `packages/rates/src/snapshots.ts`,
  `packages/rates/src/snapshots.test.ts`.

## Comments

Ревью 16 августа: пришедшие, пока идёт первый запрос, получали пустоту
из-за признака, выставленного синхронно, — доска бота выходила дырявой.
Исправлено: идущий запрос дожидаются все (`inFlight` раньше признака),
закреплено тестом «пришедшие следом делят с первым один запрос и один
ответ». Мёртвые `return known` заменены честной пустотой, правило
свежести одно на показ и фильтр.
