# Спека: курс есть всегда

## Допущения

Приняты по ходу разбора. Если хоть одно неверно — работа меняется.

1. **Курс фиата и USDT стабилен настолько, что минутная давность не
   имеет цены.** Решение владельца, высказано прямо: «у нас фиатные
   валюты и stablecoin usdt, у них нет такого как в мемкоинах где курс
   скачет каждую секунду».
2. **«Курс назовёт менеджер» — не рабочее состояние, а поломка.** Оно
   остаётся только там, где котировки нет ни у одного провайдера.
3. Трафик сервиса низкий и останется таким в ближайшее время: 3 заявки
   за две недели по боевой базе на 16 августа 2026.
4. Провайдеры отвечают быстро и не падают — замерено с боевого сервера,
   ни одного отказа в журнале за всё доступное окно.
5. Менять схему базы не требуется.

## Objective

Клиент открывает Mini App или жмёт «Курс» в боте — и видит курс. Всегда,
из памяти, без ожидания. Сегодня он видит «курс назовёт менеджер» и ждёт
до тридцати секунд, пока приложение спросит снова.

Успех — это отсутствие пропаж, а не скорость ответа саму по себе: ответ и
сегодня быстрый, когда снимок жив.

### Отчего курс пропадает сейчас

Три причины, все подтверждены на боевом контуре 16 августа 2026.

**Первая — снимок протухает раньше, чем приходит клиент.** Снимок живёт
`maxAgeMs = 5 минут`, а обновляется только тогда, когда кто-то спросил:
периодического обновления нет, `warmUp()` отрабатывает один раз при
запуске процесса. При трёх заявках за две недели пауза между живыми
клиентами — часы, и снимок мёртв к приходу каждого.

**Вторая — протухший снимок отдаётся пустотой, хотя провайдер жив.**
`snapshots.ts:163` отдаёт старый снимок и уходит обновляться в фоне, а
`snapshots.ts:182` тут же выбрасывает его по потолку — клиент получает
пусто, притом что провайдер ответил бы за две десятых секунды.
Воспроизведено тестом с подменным временем:

```
первый визит: ПУСТО; следующий опрос: курс есть; запросов к провайдеру: 3
```

**Третья — просроченный `initData` убивает обновление на висящей
сессии.** Подпись живёт сутки (`init-data.ts:35`), экран просит курс
каждые тридцать секунд и получает 401, а `exchange-screen.tsx:449`
молча гасит курс в `null`. Курс не вернётся никогда — до переоткрытия
Mini App. Прямо сейчас на боевом такая сессия висит: 445 строк в журнале,
все одинаковые, ровно через 31 секунду.

Побочно из этого следует, что висящий клиент кэш не греет: `requireInitData`
стоит первой строкой маршрута, до ядра дело не доходит.

### Замеры, на которых стоят решения

Провайдеры с боевого сервера, по 3–8 заходов:

| Провайдер | Время | Объём |
|---|---|---|
| ЕЦБ (frankfurter) | 0,04 с | 435 б |
| Kraken | 0,05–0,37 с | 625 б |
| Bitkub | 0,04–0,61 с | 204 б |
| HTX P2P | 0,19–0,50 с | 8 КБ |
| Rapira | 0,40–0,56 с | 4 КБ |

Первый замер Bitkub показал 95 КБ и 2,5 секунды — он бил по эндпоинту
без параметра, а источник спрашивает одну пару (`sym=USDT_THB`) и
получает двести байт. Ошибка замера, не свойство провайдера.

Настройки сервиса на боевом: наценка 200 bps, неоплаченная заявка живёт
120 минут. То есть **сервис уже держит зафиксированный курс два часа** —
на этом фоне пятиминутный потолок показа неоправданно жёсток.

## Tech Stack

Без изменений: TypeScript, pnpm + turbo, vitest. Правка целиком в
`packages/rates`, `apps/miniapp`.

## Commands

```
Тесты пакета:      cd packages/rates && pnpm run test
Тесты приложения:  cd apps/miniapp && pnpm run test
Всё разом:         pnpm -r run test
Типы:              pnpm -r run typecheck
Линт:              pnpm -r run lint
```

`globalSetup`.

## Code Style

Как в проекте: объяснение «почему» рядом с кодом, не «что». Пример из
правки:

```ts
/*
 * Снимок обновляется сам, пока процесс жив, — не ради свежести, а ради
 * того, чтобы он не умер к приходу клиента. Обновление по запросу
 * работает, только когда запросы идут подряд; при трёх заявках за две
 * недели каждый клиент приходил на мёртвый снимок и слышал «курс
 * назовёт менеджер» при живой бирже.
 */
```

## Testing Strategy

vitest, тесты рядом с кодом. Правило проекта: правка ошибки начинается с
падающего теста — здесь оно применяется целиком, ожидаемый ответ известен
заранее («после суток простоя клиент получает курс»).

Время в тестах подменяется через `now`, таймеры — через
`vi.useFakeTimers()`. Сети в тестах нет.

Вёрстка тестами не проверяется: сообщение о просроченной сессии смотрится
глазами.

## Boundaries

- **Всегда:** падающий тест до правки; `pnpm -r run test` до коммита;
  запись в `CHANGELOG.md` тем же коммитом; отложенное — в `backlog.md` с
  причиной.
- **Спросить сначала:** изменение схемы базы; новые зависимости; всё, что
  меняет курс уже поданных заявок.
- **Никогда:** не трогать боевой контур руками; не удалять существующие
  тесты; не отдавать клиенту курс, которого сервис не готов держать.

## Решение

### 1. Снимок обновляется сам, пока процесс жив

Таймер в `snapshots.ts` с периодом `ttlMs`. Снимок не доживает до
потолка, и клиент всегда попадает в тёплый кэш.

Таймер `unref()`, чтобы не держать процесс; заводится вместе с прогревом
и живёт столько же, сколько процесс.

### 2. Сроки — под стабильные валюты

| Провайдер | `ttlMs` было | стало | `maxAgeMs` было | стало |
|---|---|---|---|---|
| Rapira | 10 с | 60 с | 5 мин | 1 час |
| Bitkub | 10 с | 60 с | 5 мин | 1 час |
| Kraken | 10 с | 60 с | 5 мин | 1 час |
| HTX P2P | 60 с | 60 с | 5 мин | 1 час |
| ЕЦБ | 1 час | 1 час | 24 часа | 24 часа |

`ttlMs` поднят потому, что теперь он задаёт и частоту фонового
обновления: десять секунд означали бы 8 640 запросов в сутки на каждого
провайдера — круглосуточный стук в чужой публичный API при полном
отсутствии клиентов. Шестьдесят секунд дают 1 440. Трафик тут ни при чём
— ответы копеечные, — а вот число обращений к недоговорным адресам вроде
P2P-раздела HTX имеет цену. Минутная давность курса на стабильных
валютах не стоит ничего.

`maxAgeMs` — не «как часто обновлять», а «сколько ещё можно показывать,
если провайдер лёг». Час против пяти минут: сервис и так несёт курсовой
риск два часа после подачи при наценке в два процента, и курс часовой
давности в эту наценку укладывается. Пустой экран стоит дороже.

Цена в памяти: снимков хранится `ceil(maxAge/ttl)+1` — было 31, станет
61. Считано на Bitkub, самом тяжёлом: около 15 МБ при 160 МБ, которые
контейнер занимает сейчас, и 4,9 ГБ свободных на сервере.

### 3. Протухший снимок не отдаётся пустотой

Если показывать нечего — снимка нет вовсе или он старше потолка, — клиент
ждёт обновления, как ждёт его первый клиент после запуска. Ждать 0,2–2,5
секунды честнее, чем сказать «курса нет» при живой бирже.

Ожидание остаётся одно на всех: пока провайдер лежит, второй и третий
клиент от своего ожидания ничего не выигрывают. Но признак «уже ждали и
не дождались» сбрасывается удачным обновлением — иначе после первого же
протухания ждать не станет никто.

С таймером это страховка, а не рабочий путь: срабатывает, только если
провайдер лежал весь час. Поэтому такое ожидание пишется в журнал —
сейчас о пропаже курса в логах нет ни строки, и жалобу нечем проверить.

### 4. Экран говорит о просроченной сессии

На 401 — «сессия устарела, откройте приложение заново» вместо
молчаливого гашения курса. Иначе человек видит «курс назовёт менеджер» и
не догадывается, что достаточно переоткрыть Mini App.

## Success Criteria

1. Клиент, пришедший после любого простоя, получает курс из памяти без
   ожидания. Проверяется тестом: сутки без обращений — `read()` отдаёт
   снимок.
2. Снимок, протухший при живом провайдере, приводит к ожиданию, а не к
   пустоте. Тест на подменном времени.
3. Признак «уже ждали» сбрасывается удачным обновлением. Тест.
4. Таймер один на кэш, не заводится вторым вызовом, не держит процесс.
   Тест.
5. Бот на «Курс» после простоя отвечает курсами, а не `RATES_UNAVAILABLE`.
6. Экран на просроченный `initData` называет причину.
7. `pnpm -r run test`, `typecheck`, `lint` — зелёные.
8. Существующие тесты не переписаны под новое поведение там, где старое
   было верным.

## Отложено, с причиной

Идёт в `backlog.md`:

- **Снимок не переживает перезапуск.** После выкатки кэш пуст, и пока
  прогрев не отработал, курса нет. Хранение снимка в базе это решило бы,
  но требует схемы, а окно — секунды после рестарта, и клиент в него
  почти не попадает.
- **Три запроса в базу на каждую котировку.** `hasActivePair`,
  `readFeeSchedule`, `readServiceSettings` — на нажатие «Курс» в боте это
  48 запросов при 16 направлениях. База локальная, счёт идёт на
  миллисекунды; трогать без замера незачем.

## Open Questions

Не блокируют: работа сделана под допущения выше.

1. Час показа при лежащем провайдере — согласен ли владелец нести
   курсовой риск такой длины? Число вынесено в настройки провайдера и
   меняется одной строкой.
2. Нужен ли фоновый стук, когда клиентов нет вовсе — например, ночью?
   Сейчас таймер работает круглосуточно; можно гасить его после суток
   тишины, но это усложнение ради 1 440 запросов к публичному API.
