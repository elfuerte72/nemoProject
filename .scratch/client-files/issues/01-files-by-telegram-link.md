# Файлы по ссылке Telegram: бот принимает, панель открывает

Status: ready-for-human

Вариант A из `../research.md`, решение владельца 4 сентября 2026.
Сделано в ветке `feature/client-files`; что именно — в `../spec.md`.

## Что проверить руками на dev-контуре

1. Прислать `@devnemobot_bot` PDF, скриншот «как файл», голосовое и
   видео: каждое даёт подтверждение приёма (или ответ помощника),
   уведомление сотруднику с вложением строкой и запись в переписке.
2. Открыть каждое из панели: PDF — в соседней вкладке под своим
   именем, скриншот — картинкой в пузыре, голосовое — играет на месте.
3. Прислать файл больше 20 МБ: бот сразу отвечает про предел, в
   переписке строка «больше 20 МБ, Telegram его не отдаёт».
4. В журнале доступа — по записи на каждое открытие, и ни одной на
   недоступный файл.
5. Голосовое, видео и «кружок» открыть с iPhone в Safari: плеер
   играет, а не пишет «не показалось». В журнале доступа после
   прослушивания — одна строка, а не пять.
6. Прислать живое фото с iPhone (Live Photo): в переписке статичный
   кадр, а не потерянное сообщение.
7. Во время прогона записать по одному обновлению каждого рода для
   фикстур `attachments.test.ts` (долг в `backlog.md`).
