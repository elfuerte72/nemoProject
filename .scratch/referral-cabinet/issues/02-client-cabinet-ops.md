# Операции кабинета клиента: счёт, сводка за период, рефералы, QR

Status: ready-for-agent
Этап: 2
Blocked by: 01

`getBonusAccount` расширяется до вида кабинета (спека, «Операции
ядра»): `lines[]` по глубине с `count`, `rateBps`, `source`, `tierName`;
`tier` — текущий, следующий, активных рефералов, сколько до
следующего; `codes` — действующие с видом и названием; `canEnterPromo`.
`referralCode` из вида уходит; Mini App и бот берут основной код из
`codes`.

`referral-cabinet-stats.ts`: `summarizeReferralCabinet(actor, period,
{offsetMinutes})` по образцу `summarizeMerchant` и теми же помощниками
`analytics.ts`: текущий и прошлый период — пришли по линиям, стали
активными (первая исполненная заявка в периоде), начислено, выплачено;
`pending` без периода; оборот приведённых по валютам отданной стороны
исполненных в периоде заявок рефералов до глубины; дни за две недели
(пришли, начислено); по кодам — пришли и начислено с первой линии.
Один пакет запросов, `cache` не нужен — Mini App зовёт маршрутом.

`listMyReferrals(actor, {line?, after?, afterId?})` — обезличенные
строки по спеке, курсор по паре «дата прихода, идентификатор», предел
50. Имён и идентификаторов рефералов в ответе нет — закрепить тестом на
форму ответа.

Маршруты Mini App: `GET /api/bonus-account` (расширенный вид),
`GET /api/referral-stats?from&to&offset`, `GET /api/referrals?line&after&afterId`,
`GET /api/referral-codes`, `POST /api/referral-codes`,
`POST /api/referral-codes/[id]/archive`, `POST /api/promo` (ввести чужой
промокод), `GET /api/referral-qr/[code].png` — публичный, только для
действующего кода, PNG через `qrcode` (зависимость Mini App серверная),
`cache-control` на сутки; неизвестный код — 404.

Тесты ядра: сводка на сиде с известными числами (пришли/активные/
начислено/выплачено и сравнение с прошлым периодом), оборот в двух
валютах не складывается, реферал третьей линии при глубине два в
сводку не попадает, дни по часам Бангкока, курсор списка на строках с
одной датой, чужой клиент в списке не виден.
