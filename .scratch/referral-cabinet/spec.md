# Спека: реферальный кабинет клиента в Mini App

Дата: 8 сентября 2026. Решения по четырём вопросам приняты Пенкиным в
тот же день: кабинет живёт в Mini App; гибкость — личные ставки,
несколько ссылок и промокодов, уровни по результату, глубина больше
двух линий; статистика — по периодам, оборот приведённых, список
рефералов обезличенно, динамика по дням. На вопрос о функциях сверх
статистики ответа не было: взят минимум, без которого остальное не
работает (см. «Допущения»). Тикеты — в `issues/`.

Основание: раздел «Профиль» Mini App сегодня и есть реферальный
кабинет — баланс, «заработано всего», две линии со счётчиками и
ставками, одна ссылка, вывод на реквизит, история. Ставки одни на весь
сервис, у клиента один код, статистики по периодам нет, имён рефералов
клиенту не показывают намеренно (`bonus-account.ts`). Владелец хочет
кабинет гибче и со всей статистикой.

## Термины (в `CONTEXT.md`)

- **Глубина программы** — сколько линий сервис оплачивает: одна и
  больше, не глубже пяти. Задаёт администратор.
- **Ставка линии** — как была: доля дохода по заявке рефереру этой
  линии, в базисных пунктах. Теперь у неё три источника, по
  старшинству: **личная ставка** клиента, ставка **уровня**, базовая
  ставка линии.
- **Уровень** — ступень программы с порогом по числу **активных
  рефералов** первой линии и своими ставками линий. Уровней может не
  быть вовсе — тогда действуют базовые ставки.
- **Активный реферал** — реферал, у которого есть хотя бы одна
  исполненная заявка.
- **Личные ставки** — ставки линий, назначенные администратором
  конкретному клиенту поверх уровней и базовых. Слово «партнёр» для
  такого клиента по-прежнему не используется.
- **Реферальный код** — то, по чему приходит реферал. У клиента их
  несколько: **ссылки** (код сгенерирован, у ссылки есть название —
  «сторис», «канал») и **промокоды** (слово, которое клиент выбрал сам
  и которое знакомый вводит в Mini App).

## Главные решения

**Цепочка хранится на всю возможную глубину, платится по настроенной.**
При регистрации по коду в `referrals` пишутся строки для всех предков
до пятой линии (`MAX_REFERRAL_DEPTH = 5`), а не до текущей глубины:
администратор, углубивший программу позже, не должен обнаружить, что
у старых цепочек третьей линии нет. Начисляется по линиям не глубже
настроенной глубины на момент исполнения заявки. Ставка каждого
начисления по-прежнему пишется в строку движения — прошлое от смены
настроек не меняется.

**Старшинство ставок: личная → уровень → базовая, по каждой линии
отдельно.** Считается для реферера в момент начисления
(`effectiveReferralRates`). Уровень определяется числом активных
рефералов первой линии *реферера* на этот момент: пороги задаёт
администратор, берётся самый высокий из достигнутых. Порог по обороту
рефералов не берётся: оборот в разных валютах не складывается
(ADR-0013), а исторического курса у сервиса нет.

**Коды — таблица, а не колонка.** `referral_codes` с видом (`link` |
`promo`), названием, архивом; у клиента до десяти действующих;
последняя действующая ссылка не архивируется — её шлёт бот и лист
«Пригласить». Клиенту без единой ссылки (след окна выката) она
заводится при первом чтении. Колонка
`clients.referral_code` остаётся на одну выкатку неиспользуемой и
обнуляемой (expand/contract): Mini App старой сборки читает её до
своей пересборки, и удалить её сразу значило бы уронить его на минуту
выката. Удаление — отдельной миграцией после выката (запись в
`backlog.md`). Кто по какому коду пришёл, хранится у реферала
(`clients.referred_via_code_id`): по этому считается статистика по
ссылкам.

**Промокод вводится после регистрации, но только пока клиент чист.**
Привязка реферера сегодня возможна только при первом запуске по
ссылке. Промокод по природе вводят руками, часто уже открыв
приложение, — поэтому операция `bindReferrerByPromoCode` привязывает
реферера клиенту, у которого ещё нет реферера и нет ни одной заявки на
обмен. Клиент с заявками — уже клиент сервиса, и приписывать его
рефереру задним числом значило бы платить за того, кого никто не
приводил. Свой код, как и раньше, не привязывает; код своего реферала
на любой глубине — тоже, иначе цепочка замкнулась бы в кольцо.
Принимается код любого вида: знакомый мог продиктовать и код ссылки.
Вводится только в Mini App: бот `/start <код>` по-прежнему не разбирает (причина в
`bot.ts` — там `telegram_user_id` не подтверждён подписью initData);
`/promo` в боте — `backlog.md`.

**Промокод — слово клиента.** От четырёх до шестнадцати знаков,
латиница и цифры, хранится и сравнивается без учёта регистра;
уникален среди всех кодов обоих видов. Слова из стоп-списка
(`tobee`, `admin`, `support`, `nemo`) не принимаются. Ссылки
по-прежнему генерируются десятизначным кодом без похожих знаков.

**Статистика клиенту считается сервером и по правилам ADR-0013.**
Период из запроса, полночь по часам браузера (смещение приходит с
запросом, как в кабинете мерчанта), сравнение с равным периодом прямо
перед выбранным, валюты не складываются. Рефералы «пришли» по дате
регистрации, «стали активными» по дате первой исполненной заявки,
«начислено» по дате начисления, «выплачено» по дате списания. Столбики
по дням за две недели — готовыми числами, а не суммами на клиенте
(`backlog.md`, «Прирост баллов за период»).

**Список рефералов обезличен, как и был.** Строка: когда пришёл,
линия, название ссылки или промокод (только у первой линии), активен
ли, сколько исполнил заявок, сколько принёс баллов, когда обменивал в
последний раз. Ни имени, ни ника, ни идентификатора.

**Правка баллов из панели — движение вида `adjustment`.** Вид в схеме
есть, операции не было. Администратор начисляет или снимает баллы с
обязательным комментарием; снять ниже нуля нельзя; кто правил, пишется
в строку (`staff_id`). Нужна вместе с личными ставками: там, где
ставка назначена руками, ошибка правится тоже руками.

## Схема (миграция `0031_referral_program`)

- `referral_line_rates`: `line` (PK, 1..5), `rate_bps` (0..10000).
  Строки определяют глубину. Данные: две строки из
  `service_settings.referral_line1_bps` / `line2_bps`; сами колонки
  остаются на одну выкатку неиспользуемыми (схема их не объявляет) и
  снимаются следующей миграцией вместе с `clients.referral_code` —
  expand/contract, как ниже.
- `referral_tiers`: `id`, `name`, `min_active_referrals` (уникально,
  ≥ 1), `created_at`. `referral_tier_rates`: `tier_id`, `line`,
  `rate_bps`, PK по паре. Уровень без ставки для какой-то линии
  наследует базовую.
- `client_referral_rates`: `client_id`, `line`, `rate_bps`, PK по паре.
- `referral_codes`: `id`, `client_id`, `code`, `kind` (enum
  `referral_code_kind`: `link`, `promo`), `label`, `created_at`,
  `archived_at`; уникальный индекс по `upper(code)`. Данные: по строке
  вида `link` с названием «Основная» на каждого клиента из
  `clients.referral_code`; сама колонка становится nullable и больше
  не пишется.
- `clients.referred_via_code_id` → `referral_codes.id`.
- `referrals`: check линии `between 1 and 5` вместо `in (1, 2)`.
- `bonus_transactions.staff_id` → `staff.id`, для правок.

## Операции ядра

Клиенту (`Actor` клиента):

- `getBonusAccount` — расширяется до вида кабинета: `balance`,
  `earned`, `minWithdrawalAmount`, `history` как были; вместо
  `line1Count/line2Count/line1Bps/line2Bps` — `lines: {line, count,
  rateBps, source}[]` по настроенной глубине; `tier: {current, next,
  activeReferrals, toNext} | null`; `codes` — действующие коды;
  `canEnterPromo` — нет реферера и заявок.
- `summarizeReferralCabinet(actor, period, {offsetMinutes})` —
  текущий и прошлый период: пришли (по линиям), стали активными,
  начислено, выплачено; `pending` (открытые выводы, без периода);
  оборот приведённых по валютам отданной стороны за период; дни за две
  недели (пришли, начислено); по кодам: пришли и начислено с первой
  линии.
- `listMyReferrals(actor, {line?, after?})` — обезличенный список с
  курсором по паре «дата прихода, идентификатор», по 50.
- `createReferralCode(actor, {kind, label, code?})`,
  `archiveReferralCode(actor, id)`, `listReferralCodes(actor)`.
- `bindReferrerByPromoCode(actor, code)`.
- `registerClient` — цепочка до пятой линии, код из таблицы любого
  вида, `referred_via_code_id`.

Сотруднику:

- `getReferralProgram()` — линии и уровни; администратору
  `updateReferralLines(actor, [{line, rateBps}])` (глубина — длина
  списка, 1..5), `upsertReferralTier`, `deleteReferralTier`,
  `setClientReferralRates(actor, clientId, rates | null)`,
  `adjustBonus(actor, clientId, {amount, comment})`. Всё — в журнал
  настроек (`recordSettingsChange`), правка баллов — движением.
- `summarizeReferrals` — на N линий; `getClientCard` — приведено по
  линиям списком, уровень, личные ставки, коды.

Внутри: `effectiveReferralRates(executor, referrerId)` — одна функция
на начисление и на показ клиенту, чтобы ставка на экране и ставка в
начислении не разошлись; `accrueReferralBonuses` идёт по линиям до
глубины и берёт ставку из неё.

## Mini App, раздел «Профиль»

Сверху как было: баланс, «заработано всего», кнопки «Вывод» и
«Пригласить». Дальше:

- **Уровень и ставки**: имя уровня, ставки по линиям с источником
  словами («личная», «уровень „Серебро“»), полоса до следующего уровня
  — «ещё 3 активных реферала». Без уровней — просто ставки.
- **Статистика**: ряд фильтров по образцу истории (`.filters`):
  сегодня, 7, 30, 90 дней; плитки «пришли», «стали активными»,
  «начислено», «выплачено» с сравнением с прошлым периодом; столбики
  по дням за две недели разметкой на CSS (библиотек графиков в Mini
  App нет и не будет ради одной полосы); оборот приведённых строкой по
  валютам.
- **Рефералы**: первые строки списка и лист «Все рефералы» с
  дочитыванием по курсору.
- **Ссылки и промокоды**: список кодов с названием, копированием,
  «поделиться» в Telegram и QR (лист; картинка — публичным маршрутом
  `GET /api/referral-qr/<код>.png` на сервере через `qrcode`, который
  уже есть у панели: в бандл Mini App библиотека не едет). Добавить
  ссылку с названием; добавить промокод словом; архивировать.
  Статистика по кодам — рядом с каждым.
- **Есть промокод?** — поле ввода, пока `canEnterPromo`.
- Вывод и история — как были.

Раздел перечитывает своё по счётчику возвращений, как сейчас; период
статистики — своим запросом при смене фильтра.

## Панель

- Настройки, новый подраздел **«Рефералка»** (`/settings/referral`):
  линии (добавить/убрать, процент каждой), уровни (название, порог,
  проценты по линиям), минимальная сумма вывода переезжает сюда из
  «Экономики». Только администратору.
- Карточка клиента: приведено по линиям списком, уровень, личные ставки
  (форма администратору), коды, правка баллов раскрытием строки с
  комментарием (администратору).
- Раздел «Рефералка»: плитки на N линий, число уровней.
- Уведомления `referral-joined` и `bonus-accrued` — слова для линии
  1..5; справка консьержа о ставках — по линиям списком.

## Допущения (ответа не было)

Сверх статистики делаются: QR и «поделиться» (без них список ссылок
неполон), правка баллов из панели (без неё личные ставки не
исправить). Не делаются и уходят в `backlog.md` с причиной: оплата
баллами части заявки (решение о деньгах), сводка раз в неделю ботом
(отдельный текст и планировщик), порог уровня по обороту, `/promo` в
боте, удаление `clients.referral_code`.

## Критерии готовности

- Клиент, пришедший по промокоду знакомого до первой заявки, привязан;
  его заявка после исполнения начисляет баллы всем предкам до
  настроенной глубины по ставкам старшинства «личная → уровень →
  базовая», и в кабинете реферера те же ставки, что в начислении.
- Администратор задал три линии и два уровня, назначил одному клиенту
  личную ставку — всё это видно в журнале настроек, а начисления
  прошлого не изменились.
- Статистика за 7 дней в Mini App совпадает с числами, посчитанными по
  базе руками на сиде; валюты оборота не складываются.
- Тесты ядра и Mini App зелёные; `bot-slop.ts` проходит новые тексты.

## Границы

- **Всегда:** операции ядра с падающего теста на настоящей базе;
  деньги строками через `Money`; статистика считается сервером; имена
  рефералов клиенту не показываются; `CHANGELOG.md` тем же коммитом.
- **Спросить сначала:** глубина больше пяти; порог уровня не по числу
  активных; оплата баллами.
- **Никогда:** аккаунты клиентам вне Telegram (ADR-0004); ставка от
  суммы сделки вместо дохода (ADR-0003); пересчёт прошлых начислений
  при смене ставок.
