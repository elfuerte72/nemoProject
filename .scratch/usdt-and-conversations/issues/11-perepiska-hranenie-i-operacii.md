# 11 — Переписка: хранение и операции

**What to build:** разговор менеджера с клиентом переезжает внутрь системы. Сообщение клиента боту сохраняется и становится обращением; ответ менеджера сохраняется и уходит клиенту ботом — тем самым, которого клиент запустил сам, и потому доступным даже при закрытых личных сообщениях. Это тикет схемы и операций ядра; экраны идут отдельно.

**Status:** ready-for-agent

- [ ] Заводится таблица сообщений: направление, текст, автор из числа сотрудников для исходящих, необязательная ссылка на заявку
- [ ] Лента одна на клиента: тредов по заявкам нет, потому что у клиента в Telegram одно окно
- [ ] Сообщение клиента боту сохраняется входящим
- [ ] Ответ менеджера сохраняется исходящим и возвращает уведомление для доставки — доставку выполняет адаптер, как у переходов заявки
- [ ] Неотвеченным считается клиент, у которого последнее сообщение входящее; отдельного поля состояния для этого не заводится
- [ ] Подтверждение приёма отправляется клиенту один раз — пока последним сообщением остаётся входящее
- [ ] Клиент не может прочитать переписку другого клиента
- [ ] Термины обращения и переписки добавляются в глоссарий
- [ ] Соответствующая запись из `backlog.md` убирается
