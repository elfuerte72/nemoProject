# 05 — Реквизиты: форма и выбор при подаче

**What to build:** клиент перестаёт угадывать, какие поля заполнять. Он сначала выбирает способ получения, потом видит ровно свои поля — и все они обязательны. Сохранённые записи показываются списком там же, где подаётся заявка; при подаче подставляется подходящая. Это тикет, после которого покупка USDT через приложение становится возможной.

**Blocked by:** 04

**Status:** ready-for-agent

- [ ] Форма реквизитов начинается с выбора способа: по номеру телефона, на карту, на кошелёк
- [ ] После выбора показываются только поля этого способа, и кнопка сохранения гаснет, пока они не заполнены
- [ ] У кошелька сеть выбирается из активных; выбранная сеть видна рядом с полем адреса
- [ ] Сохранённые записи показываются списком с короткой подписью: банк и последние четыре цифры, банк и телефон, сеть и края адреса
- [ ] Запись можно удалить из того же списка
- [ ] Список и добавление живут в листе с экрана обмена — уходить в другой раздел посреди заполнения формы клиент не должен
- [ ] При подаче заявки показываются только подходящие к валюте получения записи
- [ ] Подставляется запись из последней заявки клиента с той же валютой получения
- [ ] При наличном обмене реквизиты не спрашиваются и в форме не показываются
- [ ] Клиент видит сумму получения без вычета комиссии сети: её платит сервис
