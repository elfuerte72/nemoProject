# 04 — Реквизиты: типы и список

**What to build:** реквизит клиента начинает описывать один способ получения денег целиком, а не набор необязательных полей. Типов три: перевод по номеру телефона, перевод на карту, перевод на криптокошелёк. Хранится список записей вместо единственной активной. Это тикет схемы и операций ядра — экраны идут отдельно.

**Blocked by:** 03

**Status:** ready-for-agent

- [x] У записи реквизита появляется тип; набор обязательных полей определяется типом и проверяется ограничением в базе, а не только формой
- [x] Перевод по телефону требует банк и телефон; на карту — банк и номер карты; на кошелёк — сеть и адрес
- [x] Запись с полями чужого типа — сетью у карты, номером карты у кошелька — отвергается базой
- [x] Правило «одна активная запись, новая архивирует старую» отменяется: клиент хранит сколько нужно
- [x] Операция сохранения перестаёт дописывать незаполненные поля из предыдущей записи
- [x] Адрес кошелька шифруется тем же способом, что номер карты, и хранится с открытой подсказкой — началом и концом адреса
- [x] Ни одна операция чтения не возвращает клиенту адрес или номер карты целиком
- [x] Появляются операции чтения списка и удаления записи; удаление архивирует, потому что на запись ссылаются исполненные заявки
- [x] Заявке на получение рублей подходят перевод по телефону и на карту, заявке на получение USDT — только кошелёк; заявка с неподходящим реквизитом отвергается
- [x] Наличная заявка подаётся без реквизитов, как сейчас
- [x] Реквизит с выключенной администратором сетью не предлагается при подаче
- [x] Термины реквизита и его типов добавляются в глоссарий
