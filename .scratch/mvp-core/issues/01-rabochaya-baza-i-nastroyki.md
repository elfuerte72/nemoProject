# 01 — Рабочая база и настройки сервиса

**What to build:** разработчик может поднять Postgres локально, применить миграцию и запускать тесты против настоящей базы. Появляются настройки сервиса — ставки линий, минимальная сумма вывода — со значениями по умолчанию, чтобы последующие тикеты не ждали экрана управления ими.

**Blocked by:** None — can start immediately.

**Status:** ready-for-agent

- [x] Установка и запуск Postgres описаны в README: одна команда поднимает базу разработки
- [x] Миграция применяется к пустой базе без ошибок. Если вскроется расхождение со схемой — миграция перегенерирована начисто, а не залатана второй: данных нет, история миграций пока ничего не стоит
- [x] Настройки сервиса содержат ставку первой линии, ставку второй линии в базисных пунктах и минимальную сумму вывода; при применении миграции заполняются значениями по умолчанию
- [x] Тесты поднимают отдельную тестовую базу, применяют к ней миграции и очищают данные между тестами
- [x] Пример теста доказывает, что обвязка работает: попытка перевести заявку в «исполнена» без указания дохода отвергается самой базой, а не кодом

## Comments

Расхождений со схемой при первом применении не вскрылось: `0000` легла на
пустую базу без ошибок, перегенерировать её не потребовалось. Таблица
настроек добавлена отдельной миграцией `0001` — это новая сущность, а не
заплатка к существующей; строка настроек создаётся там же, значения берутся
из `DEFAULT` колонок, чтобы второго места для них не появилось.

Постгрес отдаёт `NOTICE` об усечении длинного имени внешнего ключа
`requisite_access_log_exchange_request_id_exchange_requests_id_fk` — оно
длиннее 63 символов. На работу не влияет, но при следующей правке схемы
имя стоит задать явно: усечённое и полное имена могут разойтись в diff
drizzle-kit.
