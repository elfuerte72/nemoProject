# 16 — Согласие на рассылку и ручные рассылки

**What to build:** при первом входе клиент решает, присылать ли ему предложения, и может отписаться в любой момент одной кнопкой. Администратор отправляет рассылку из админки — только тем, кто согласился.

**Blocked by:** 02, 05

**Status:** ready-for-agent

- [x] При первом входе клиент отвечает на вопрос о согласии на рассылку
- [x] Клиент отписывается одной кнопкой; согласие снимается немедленно
- [x] Администратор составляет и отправляет рассылку из админки
- [x] Сообщения уходят только клиентам с действующим согласием
- [x] Отправка учитывает ограничения Telegram на частоту и не роняет бота на большом списке
- [x] Клиенты, заблокировавшие бота, не ломают рассылку остальным
- [x] Администратор видит результат отправки: сколько доставлено, сколько не удалось

## Comments

Разделение по слоям: список получателей отдаёт операция ядра, отправку с
оглядкой на ограничение Telegram по частоте выполняет `@nemo/telegram`,
результат возвращается в ядро отдельным вызовом. Ядро в сеть не ходит,
но и счётчик доставки не должен считаться в маршруте.

Отправка идёт порциями по 25 сообщений в секунду с паузой: превышение
лимита Telegram стоит временной блокировки бота, и пострадала бы не
только рассылка, но и уведомления по заявкам. Отказ по одному
получателю — включая заблокировавших бота — не прерывает остальных и
попадает в счётчик недоставленных.

Список получателей берётся целиком, без страниц: на тысячах клиентов
экономия незаметна, а отправка усложнилась бы. Когда их станет на
порядок больше, поменяется операция, а не каждый вызывающий её экран.
