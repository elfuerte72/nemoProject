# 10 — Реферальные начисления при исполнении заявки

**What to build:** в момент, когда заявка становится исполненной, обе линии рефереров получают баллы — процент от дохода сервиса по этой сделке. Это единственная точка начисления во всей системе.

**Blocked by:** 07

**Status:** ready-for-agent

- [x] Исполнение заявки начисляет баллы рефереру первой линии по ставке из настроек
- [x] Если у реферера есть свой реферер, начисление получает и вторая линия по своей ставке
- [x] База начисления — доход по заявке, а не её сумма
- [x] Повторный вызов исполнения не создаёт второго начисления; защита обеспечена ограничением базы, а не проверкой в коде
- [x] Исполнение заявки клиента без реферера начислений не создаёт
- [x] Начисление и смена статуса выполняются в одной транзакции: откат одного откатывает другое
- [x] Реферер получает уведомление о начислении

## Comments

Ставка, по которой начислено, сохраняется в самой строке движения
(`bonus_transactions.rate_bps`). Без этого смена ставок в тикете 14
переписывала бы уже сделанные начисления.

Валюты у балла нет, и это ограничение модели, а не недосмотр: перевод
дохода в баллы по курсу ждёт блокера B3 («цена балла»). Пока доход и
балл считаются одной величиной, и сервис, работающий в двух валютах
расчёта, сложит их в один баланс. Колонку валюты в движение баллов
намеренно не заводили — с ней «бонусный баланс» перестал бы быть одним
числом, каким его описывает тикет 11.

Нулевое начисление (ставка линии 0) строки не создаёт: она ничего не
меняет в балансе и только засоряет клиенту историю.
