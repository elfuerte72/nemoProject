# 14 — Административные настройки

**What to build:** администратор управляет сотрудниками и экономикой сервиса — наценками по направлениям, ставками реферальных линий и минимальной суммой вывода — не трогая код.

**Blocked by:** 05

**Status:** ready-for-agent

- [x] Администратор добавляет сотрудника, назначает ему роль и отключает доступ
- [x] Менеджер не имеет доступа к разделу настроек
- [x] Администратор настраивает наценку по каждому валютному направлению
- [x] Администратор настраивает ставки первой и второй линии
- [x] Администратор задаёт минимальную сумму вывода
- [x] Изменение ставок не пересчитывает уже сделанные начисления — прошлые сделки остаются с теми условиями, при которых были исполнены
- [x] Изменения настроек записываются с указанием, кто и когда их внёс
- [x] Второй фактор сотруднику выдаёт и сбрасывает администратор: секрет, который заводится сам при первом входе, отдаёт админку тому, кто угнал аккаунт до этого входа — второй фактор не срабатывает ровно в том случае, ради которого заведён

## Comments

Самозапись второго фактора при первом входе убрана — с ней тикет 05
закрывал не ту угрозу, ради которой второй фактор заводится. Теперь
секрет выдаёт администратор при заведении сотрудника и сбрасывает его
через `resetStaffSecondFactor`; показывается он один раз.

Отсюда вырос бутстрап: пока сотрудников нет, выдать секрет некому.
Появилась операция `enrollFirstAdmin`, работающая только на пустом
списке, и скрипт `pnpm create-first-admin`. Скрипт, а не экран: открытый
в сети адрес «сделать себя администратором» на свежем деплое достался бы
тому, кто нашёл его первым. Заодно добавлен `pnpm generate-keys` —
README требовал ключи шифрования, но выпустить их было нечем.

Администратор не может отключить самого себя: второго администратора в
сервисе может не быть, и вернуть доступ было бы некому.

Наполнение справочника направлений в тикет не входит (блокер C1) —
настраивается наценка у уже заведённых.

Журнал изменений хранит, что именно поменялось, документом `jsonb`:
настройки разнородны — ставка в базисных пунктах, сумма вывода, роль
сотрудника, наценка направления, — и колонка под каждую означала бы
правку схемы при каждой новой настройке.
