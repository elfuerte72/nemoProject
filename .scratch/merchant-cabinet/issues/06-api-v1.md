Схема: `api_keys` (мерчант, публичная часть для показа, хеш секрета,
подпись словами, выдан, отозван, последняя активность),
`api_request_log` (время, ключ, метод, путь, код, длительность, адрес,
текст ошибки). Операции: `issueApiKey` (секрет возвращается один раз и
не хранится), `revokeApiKey`, `listApiKeys`, `authenticateApiKey`,
`logApiRequest`, `listApiRequestLog(filter, cursor)`,
`purgeApiRequestLog(olderThan)`; `merchants.signature_required` и
`setSignatureRequired`.

Адаптер `requireApiKey(request)` в `apps/cabinet/lib/api.ts`:
`Authorization: Bearer <ключ>`; при включённой подписи — `x-api-key`,
`x-timestamp`, `x-signature` по `method + path + timestamp +
sha256(body)`, окно пять минут, повтор той же подписи отвергается.
Лимит сто в минуту и тысяча в час по ключу в памяти процесса, ответ
`429` с `retry-after`. Каждый вызов пишется в журнал, в том числе
отвергнутый. Тело ошибки `{ error: { code, message } }`; коды ядра
через `statusForCoreError`.

Маршруты `/api/v1`: `GET /rates`, `POST /quote`,
`POST /exchange-requests` (обязательный `Idempotency-Key`, `reference`,
получатель `requisitesId` или `payout`, `quotedAt` по желанию;
наличные отвергаются), `GET /exchange-requests/:id`,
`GET /exchange-requests?status&after`, `POST
/exchange-requests/:id/cancel`, `GET /requisites`, `POST /requisites`,
`DELETE /requisites/:id`. Отключённому мерчанту — `401` на любой
запрос. Подача зовёт `nudgeStaffAlerts`, как Mini App.

Договор — `docs/api/merchant-v1.yaml` (OpenAPI 3.1): пишется до
маршрутов; тест перечисляет маршруты приложения и сверяет с файлом,
пример каждого ответа — фикстурой. Раздел **Документация** в кабинете
рендерит файл; раздел **API**: ключи (выпуск с показом секрета один
раз и предупреждением, отзыв, подпись словами), тумблер подписи,
лимиты, пример на Node.js с настоящим публичным ключом мерчанта;
раздел **Журнал вызовов** с плитками и фильтрами; раздел
**Песочница**: адрес тестового кабинета и чем `sk_test_` отличается.
В карточке мерчанта панели — блок ключей без секретов и последняя
активность. Письма о выпуске и отзыве ключа.

Планировщик: `POST /api/maintenance/purge-logs` с
`SCHEDULER_SECRET`, раз в сутки, по образцу README.

## Сделано 7 сентября 2026

Схема: `api_keys` (мерчант, подпись, хвост, хеш секрета, выпущен,
отозван, последний вызов) и `api_request_log`; миграция
`0029_api_keys_and_log`. Ядро: `issueApiKey` (секрет один раз, хеш
SHA-256 — у ключа 192 бита случайности), `revokeApiKey`, `listApiKeys`,
`listMerchantApiKeys` для панели, `authenticateApiKey` — размеченный
ответ, а не исключение: адаптер пишет отвергнутый вызов в журнал
мерчанта и должен знать, чей ключ отвергнут; `setSignatureRequired`;
`logApiRequest`, `listApiRequestLog` с курсором «время и номер»,
`countApiRequestLog`, `summarizeApiRequestLog`, `purgeApiRequestLog`.
Префикс ключей — `apiKeyPrefix` в `CoreConfig` из `API_KEY_PREFIX`.
Письма `merchant-api-key-issued` и `merchant-api-key-revoked` — без
самого ключа, проходят `bot-slop`.

Адаптер — `apps/cabinet/lib/v1/`, а не один `lib/api.ts`: обёртка
(`handler.ts`, ядро зависимостью и потому без базы в тесте), подпись
(`signature.ts`: строка `METHOD\npath?query\ntimestamp\nsha256(body)`
через перевод строки — склейка без разделителя подписывала бы «/a1»
и «/a»+«1» одинаково; окно пять минут; повтор отвергается памятью
процесса), предел (`rate-limit.ts`, окна по часам), схемы тел
(`schemas.ts`), виды ответов (`views.ts`), котировка с обратным счётом
(`quote.ts`: пробная единица → `usdForPayout` → та же котировка на
найденную сумму и ту же отметку). Ключ принимается и из `Authorization:
Bearer`, и из `x-api-key`. Маршруты по спеке; `POST /exchange-requests`
принимает `side: "to"` и подаёт по найденной сумме отдачи с отметкой
котировки. `GET /rates` называет курс для наименьшей суммы направления
— как черта в Mini App до набора суммы (запись в `backlog.md` о двух
копиях правила).

Схема реквизита в теле — одна на Mini App и API: `requisiteInputSchema`
переехала в `@nemo/types`, маршрут Mini App берёт её оттуда.

Кабинет: разделы «API» (`/keys` — `/api` занят маршрутами: ключи,
выпуск с показом секрета один раз, отзыв с подтверждением, тумблер
подписи, пределы, пример на Node.js с хвостом настоящего ключа и
вариант с подписью), «Журнал вызовов» (`/calls`: плитки за сутки, табы
исхода, курсор), «Документация» (`/docs`: файл OpenAPI едет в бандл
строкой правилом `asset/source`, страница рисует операции своими
деталями; сам файл — `/api/docs/openapi.yaml`), «Песочница» (`/sandbox`:
адрес из `CABINET_SANDBOX_URL`, иначе поддержка). В карточке мерчанта
панели — ключи без секретов и последняя активность. Планировщик:
`POST /api/maintenance/purge-logs` раз в сутки.

Тесты: ядро на настоящей базе (ключи, узнавание, отзыв, журнал,
курсор, плитки, чистка), подпись (сходится/не сходится по каждой
части, окно в обе стороны, повтор, память), предел (минута, час,
по ключу), обёртка (без ключа не пишется, отозванный пишется, коды и
слова, 429 с retry-after, сбой журнала не портит ответ, подпись,
повтор, чужое тело), OpenAPI ↔ маршруты и примеры у каждого ответа.
Повтор `Idempotency-Key` и неправдоподобный `payout` — тесты ядра из
тикета 01; наличную заявку API не принимает по построению — поля
`kind` в договоре нет.

Заодно, по следам живого прогона (`probe-api.mts` рядом со спекой):

- у ядра кабинета не был подключён источник курса, и любая заявка по
  API уходила без курса — «назовёт менеджер»; теперь
  `ratesFromEnvironment()` из тех же переменных, что у Mini App;
- курсор своего списка заявок (`listExchangeRequests`, тикет 01)
  сравнивал кортеж с датой сырым `sql`, и драйвер отправлял дату
  строкой: вторая страница отвечала пятисотым и в кабинете, и в API.
  Переписан типизированными операторами, как курсор очереди, и закрыт
  тестом на пять заявок с одним временем подачи;
- отказ ядра узнаётся по коду (`isCoreError` в `@nemo/http`), а не
  только по классу: в `next dev` у маршрута и у ядра разные копии
  класса, и любой отказ отвечал пятисотым — запись из `backlog.md`
  закрыта.

По следам ревью (два прохода: стандарты и спека):

- `side: "to"` с присланной `quotedAt` считал сумму отдачи по текущему
  снимку, а заявку подавал по присланному; обратный счёт шёл по
  банковской сетке, хотя способ выдачи должен идти от получателя.
  Теперь `quoteFor` принимает отметку и способ, а способ выводится из
  `payout` или сохранённой записи (`recipientPayoutMethod`);
- `afterId` журнала не проверялся и ронял маршрут исключением `BigInt`
  — отказ словами из ядра; момент вызова ставится в JS до миллисекунды,
  чтобы курсор через JSON не терял строки той же миллисекунды;
- перебор незнакомых ключей считается по адресу тем же счётчиком, что
  попытки входа: десяток чужих за четверть часа — 429;
- тела `/quote` и подачи строгие: неизвестное поле, включая `kind`,
  отвергается словами, а не выбрасывается;
- журнал сужается ещё и по ключу (чипы над таблицей); подсказки
  разделов вынесены в `lib/integration-texts.ts` и вместе с описаниями
  договора проходят `bot-slop`; примеры в договоре сверяются с формой
  ответов; `V1ErrorCode` выводится из `CoreErrorCode`;
- копии `nudgeStaffAlerts` и обратного счёта — в `backlog.md` с
  причиной.
