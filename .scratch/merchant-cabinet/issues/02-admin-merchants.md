Раздел `/merchants` в `apps/admin`, строка в `lib/nav.ts`: список с
табами «На рассмотрении», «Активные», «Отклонённые», «Отключённые» со
счётчиками (в меню — счётчик ждущих рассмотрения, считается через
`cache` вместе с остальными), поиск по названию и почте. Карточка
`/merchants/<id>`: анкета, контакты, состояние с причиной, заявки
мерчанта (та же таблица заявок с курсором), позже — ключи, вебхуки,
статистика (тикеты 06, 07, 09 дописывают свои блоки). Кнопки только
администратору: одобрить, отклонить с причиной (раскрытием строки, как
у необратимого), отключить, включить; менеджер видит без кнопок.
Подсказка «как устроено»: кто такой мерчант, что даёт одобрение, что
происходит при отключении.

Стол менеджера: у заявки мерчанта пометка «Мерчант: <название> ·
<reference>», фильтр по мерчанту в адресе, палитра ⌘K находит по
`reference` и по названию мерчанта. Карточка заявки: справа карточка
мерчанта вместо карточки клиента, переписки нет — телефон и почта из
анкеты. Уведомление сотруднику о новой заявке — с названием мерчанта
(из тикета 01).

Настройки: подраздел «Мерчанты» в `SETTINGS_SECTIONS` с одной
настройкой «аккаунт поддержки» (`merchant_support_username`, ник без
`@`), запись в журнал настроек. Одобрение и отключение — тоже в журнал.

Сид для тестового контура: скрипт по образцу
`.scratch/lovepay-crm/seed-dev.mts` заводит мерчанта в каждом
состоянии и три его заявки, чтобы раздел смотрелся глазами до появления
кабинета.

Тесты: `nav.test.ts` (раздел и счётчик), фильтр стола по мерчанту,
палитра по `reference`, права кнопок (менеджеру 403 на маршруте).
