# «Показать ещё» в очередях по курсору

Status: resolved
Blocked by: 01

Выборки стола ограничены пятьюдесятью строками, и дальше стоит строка
«показаны первые N из M — сузьте фильтром». Курсор по паре «время
подачи и идентификатор» в ядре есть с тикета 04 прошлой серии, панель
его не использует.

## Что делать

1. У каждого из трёх разделов стола — подвал из тикета 01: «Показаны
   1–50 из 137» и кнопка «Показать ещё», которая дочитывает
   следующую страницу по курсору последней строки и дописывает её в
   список, не перечитывая показанное.
2. Дочитывание — маршрутом `GET` с параметрами фильтра и курсора;
   маршрут зовёт те же операции, что и страница.
3. Автообновление по таймеру перечитывает только первую страницу и
   не сбрасывает дочитанное, пока менеджер не сменил фильтр.

## Как проверяем

Тестом — сборка курсора из последней строки и слияние страниц без
дублей (чистые функции). Остальное глазами: на 200 заявках в очереди
кнопка дочитывает, строки не дублируются, фильтр сбрасывает хвост.

## Answer

Сделано 2 сентября 2026. Курсор и склейка страниц — `apps/admin/lib/paging.ts` (тест рядом); фильтр стола в одном месте — `lib/exchange-rows.ts`, им пользуются и страница, и маршрут `GET /api/exchange-requests`. Список стола стал клиентским компонентом `exchange-table.tsx`; ключ по фильтру сбрасывает хвост. Проверено на 72 заявках в работе: дочитано без дублей.
